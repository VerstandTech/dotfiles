## Rules

### R1 — One authoring source

`rulesync.jsonc` and `.rulesync/**` are the only hand-edited source for generated always-on instructions. `AGENTS.md` is generated and must not be edited directly.

### R2 — Minimal conflict-free target map

GOV-01 generates only `agentsmd` rules at the repository root. It must not generate `.codex/**`, `.claude/**`, `.grok/**`, `.opencode/**`, or `.pi/**` outputs.

### R3 — Pinned, local, explicit execution

Generation and checking use `node_modules/.bin/rulesync` at exactly `16.9.1`. If dependencies are absent or the version differs, scripts fail clearly and never install or update anything.

### R4 — Deterministic generation and drift detection

The same canonical input generates byte-identical output twice. `generate --check` succeeds on canonical output and fails after a direct generated-output edit.

### R5 — Root BDD command is real

Root `.pi/bdd.json` points to a checked-in command that runs the GOV contract, Pi package tests, personal Pi library tests, and repository AI-resource validation. Exit 126/127 is failure, never evidence.

### R6 — Existing resources keep their owner

Rulesync does not copy, delete, or become canonical for `agents-shared/.agents/**`. The root generated rule explicitly states the ownership split.

## Questions and disposition

1. **Should Rulesync generate every vendor target now?** No. Deferred to compatibility-tested target-specific packages; root `agentsmd` only in GOV-01.
2. **Should generated outputs be ignored?** No. `AGENTS.md` is tracked so drift is reviewable and CI can check it.
3. **Should scripts call `bunx rulesync@latest`?** No. Only the checked-in exact dependency and local binary are allowed.
4. **May tests generate in the working tree?** No. Determinism and mutation fixtures use a temporary repository; the explicit generate command is the only working-tree writer.
5. **Should GOV validate deployed `$HOME` state?** No. Root regression uses repository-only validation; deployed-home acceptance remains PKG-01.
